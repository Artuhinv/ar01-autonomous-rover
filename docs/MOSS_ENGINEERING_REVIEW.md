## Что переносим как инженерный принцип

| Решение | Применение к AR-01 |
| --- | --- |
| Модульные держатели компьютера и камеры | Съёмная верхняя платформа, доступ к разъёмам, запас кабеля; размеры после выбора деталей |
| Печатные пробы соединений до корпуса | Сперва образцы посадки вала/ступицы/крепежа; габариты JGB37 измерить |
| Плавный выход + пауза реверса | Проверить MCU адаптер отдельно; MOSS проценты PWM не заменяют наш PI скорости |
| Измерение пути рулеткой против энкодеров | Калибровать знаки, counts/rev, радиус, затем базу по повороту |
| Раздельные доказательства CAD / симуляция / железо | Не объявлять надёжность на основании красивого рендера |

Гусеницы, захват, ESP32 и dimOS не подменяют нашу колёсную базу,
STM32 и интерфейс ROS. Копирование исходников/геометрии MOSS не выполнялось.
Код MOSS Apache-2.0, manufacturing hardware CERN-OHL-S-2.0;
при будущем заимствовании геометрии проверить соответствующие обязательства.

## Наши проверяемые слабые места

1. **Размещение массы.** В P0 опора — треугольник: колёса (0, ±155 мм),
   ролик (-120 мм, 0). Расчёт по массам Xacro даёт центр P0
   x=-20.92 мм, h=96.25 мм. Упрощённый худший случай уклона 5° и
   ускорения 0.5 м/с² оставляет 7.57 мм до ближайшей границы.
   Гипотеза +1 кг при x=70, z=250 мм даёт отрицательный статический запас.
   Тот же +1 кг при x=-70, z=45 мм даёт 21.62 мм под расчётной нагрузкой.
   Это чувствительность к компоновке, не измерение реального робота.
2. **Разные ограничения симуляции и MCU.** P0: timeout 0.5 с,
   скорость 0.5 м/с, ускорение 0.8 м/с². P1: timeout 0.2 с,
   целевые 0.6 м/с и 0.5 м/с². Не менять замороженный P0;
   для физической конфигурации создать отдельный профиль после проверки.
   При одинаковых гипотетических 0.6 м/с и торможении 0.5 м/с²:
   остановочный путь 0.66 м для 500 мс против 0.48 м для 200 мс.
   Сброс PWM/питания не гарантирует такое торможение: накат измерять.
3. **Подмена двигателя.** Репозиторий рассчитывает Pololu #4754,
   корзина содержит JGB37-520. Старые допуски тока, момента и энкодера
   нельзя автоматически считать подтверждёнными для китайского мотора.
4. **Печать корпуса.** Штатные детали MOSS ориентированы на иные
   габариты стола. Пример: задняя половина корпуса 203×237 мм.
   Совместимость с Kobra 2 Neo не подтверждена; нужен собственный раскрой.
5. **CAD пока открыт.** В P0 только геометрический конверт, а не
   реальные кронштейны, крепёж, ступицы и провода.

## Следующий Gazebo эксперимент

Сохранить tag P0. В отдельном физическом профиле проверить:
- 3/4 кг, низкое/высокое и переднее/заднее размещение массы;
- разгон/торможение и поворот при 0.3/0.6 м/с;
- уклон ±5° в обеих ориентациях, порог 5/10 мм как исследовательский сценарий;
- обрыв cmd_vel: остановка, максимальный путь, отсутствие самозапуска;
- разные радиусы колёс/проскальзывание: ошибка курса и одометрии.

Сначала зафиксировать измеримые критерии, затем прогнать baseline и
кандидат с одинаковыми начальными условиями. Не исправлять несуществующую
проблему заменой STM32 или всей архитектуры.

Воспроизведение аналитики: `python hardware/experiments/moss_screen.py`.
Она не требует ROS, ничего не меняет в P0 и явно печатает свои допущения.
